CipherPot — Concrete Product & Review Spec (v1 for November 14 Deadline)
A skill-based '20 Questions' deduction game powered by TEE-verified AI on NEAR Protocol
1. Product Definition & Overview
Product Name: CipherPot
One-Liner: A skill-based '20 Questions' deduction game on NEAR Protocol played over a board of 64 candidate secrets, using TEE-signed verification to settle pot claims securely on-chain.
Core Concept & Value Proposition
* For Players: Human-first, low-stakes entertainment with capped loss (entry fee) and strict guess allowances to prevent agent brute-forcing.
* For AI Agents: Autonomous earning opportunity with pre-funded contract spend limits and structured interaction endpoints.
* For the Protocol: Sustainable fixed 4% rake per solved round in a low-friction deduction game environment.
Track Alignment
* Primary Track: Games With Real Economies
* Secondary Tracks: Agent Economy, Privacy & Private AI
2. Game Design & Core Mechanics
Secret Selection Rules
* Secrets are selected from a fixed board of 64 canonical candidate secrets, ensuring clear boundaries and predictable candidate pools for deduction.
* Facts are chosen to ensure deduction skill matters while narrowing the answer space to eliminate arbitrary web-search brute forcing.
* Verification is conducted inside a Trusted Execution Environment (TEE) that cryptographically signs guess verdicts sent to the smart contract interface.
Round Lifecycle
* 1. Commitment: The secret is chosen from the published set and committed via TEE (hash + salt) before round start.
* 2. Entry & Allowances: Players pay a fixed NEAR entry fee, granting a defined question quota (up to 20 total per round across players) and a strict allowance of 3 guesses per entry fee to defeat brute-force bots.
* 3. Question Phase & AI Record: Participants submit questions. The AI answerer records structured responses (Yes / No / Unclear) with strict anti-prompt-injection controls.
* 4. Guess & Settlement: Guesses are processed via a TEE-signed verification flow. The contract verifies the TEE signature and releases the pot minus the 4% protocol rake to the correct claimer.
* 5. Rollover & Reveal: If unsolved at timeout, the pot rolls over to the next round while the commitment is revealed on-chain for auditability.
Game Modes & Monetization
* Public Daily/Hourly Rounds: Shared canonical secret set, competitive open deduction.
* Agent Integration: Autonomous AI agents participate via pre-funded contract deposit allowances.
* Protocol Revenue: Fixed 4% pot rake collected upon successful round claims (private rooms and extra monetization deferred post-MVP).
3. Architecture & Tech Stack
Smart Contract Layer & Contract Interface (NEAR)
* Single main Rust contract interface managing round lifecycle, TEE verification signatures, entry fees, pre-funded agent balances, guess quota enforcement, fixed 4% rake, rollover accounting, and admin pause controls.
* Uses native NEAR payments (USDC and Intents cross-chain payments cut from initial MVP scope for simplicity).
Backend & Answerer Service Details
* AI Answerer & TEE: Executes inside NEAR AI Cloud TEE with strict anti-prompt-injection wrappers, outputting structured records and cryptographically signed verification verdicts.
* Agent Interface & Indexer: Exposes HTTP/MCP/NEAR Agent Skill endpoints allowing autonomous AI agents to join, ask, and claim.
Frontend Requirements
* Built using Next.js/React + NEAR Wallet Selector SDK.
* Displays live pot size, questions remaining, active countdown timer, wallet connector, question feed, guess form, and claim trigger.
4. Trust, Fairness & Risk Mitigations
User Journey (Steps 1–10)
* 1. Landing & Overview: User views active pot size, countdown timer, question history, and board rules.
* 2. Wallet Connection: User connects via NEAR Wallet Selector SDK (supporting MyNearWallet, Meteor, Sender, etc.).
* 3. Entry & Quotas: User pays the entry fee to join the round, unlocking questions and guess allowances.
* 4. Secret Candidate Board: User inspects the active grid of 64 candidate secrets and filters possibilities based on revealed answers.
* 5. Question Submission: User submits yes/no deduction questions to the TEE-enforced AI answerer.
* 6. Live Feed Updates: The public question feed updates instantly with structured responses (Yes / No / Unclear).
* 7. Guess Submission: User submits a final secret guess using their strict guess quota.
* 8. Verification Flow: The backend TEE verifies the guess and issues a cryptographic verdict signature.
* 9. Claim & Settlement: If correct, user triggers pot claim; the smart contract verifies the TEE signature and releases 96% of the pot (4% rake deducted).
* 10. Rollover & Reveal: If unsolved when the timer expires, the pot rolls over to the next round and the secret commitment is revealed on-chain.

Agent Build Rules
* Endpoint Standardization: Expose structured HTTP/MCP REST endpoints alongside NEAR Agent Skill interfaces for non-browser automation.
* Pre-Funded Balance: Allow AI agents to pre-fund round entry budgets directly on the contract via explicit spend allowances.
* Quota Parity: Enforce identical guess and question rate limits on AI agents as human UI players to maintain fair competitive balance.


Risk / Challenge
	Mitigation Strategy
	Operator tampers with secret word
	TEE-enforced commitment (keccak256 + salt) and TEE-signed verification verdicts on submitted guesses.
	AI hallucination / inconsistent logic
	Strict structured system prompt and input sanitization layer to block prompt injection attacks.
	Backend outage / Server failure
	Round timeout triggers automatic pot rollover to the subsequent round rather than refunds.
	Front-running guesses
	Strict guess quotas per entry fee and pre-published candidate lists constrain the guess space.
Spectator Mode Specifications
* Default State & Read-Only Fetching: Spectator Mode is active whenever no wallet is connected. All game data (pot size, countdown timer, candidate list, and public question feed) is fetched via read-only RPC calls without requiring wallet authorization.
* Always-Visible Features: Header, 64-name secret candidate board, live question feed, rule-outs, 'Verify Fairness' link, active agents panel, and 'How to Play' instructional strip remain fully visible to spectators.
* Locked Actions & UI Banner: Interactive game actions (Submit Question, Submit Guess, Join Round) appear visible but inactive. Clicking any locked action triggers the wallet connection flow. A slim banner reading "You're watching. Connect a wallet to play." is permanently displayed at the top, along with a prompt directing users to a faucet if NEAR balance is insufficient.
* Player Local State: Local candidate cross-offs/filters work for all users including spectators, but the "You're in" participation panel is hidden until a wallet is connected and an entry fee is paid.
* Between-Round Handling: Upon settlement, the operator waits ~2 minutes before starting the next round, ensuring the 'Settled' summary screen remains visible to spectators.
* Acceptance Test: Opening the DApp in a clean private/incognito window allows full read-only viewing of board, live feed, and timers without throwing errors or requiring wallet prompt on load.
